Authentication API used by client applications to identify their users, with credentials or with a Microsoft (Azure) account.

Every example below is generated from the integration tests by Spring REST Docs: the requests were really sent and the responses really received.
The field, parameter, header and cookie tables are checked by the tests too: if the API changes and this document does not, the build fails.

[[conventions]]
== Conventions

[[conventions-authentication]]
=== Authentication

* *Access token*: short-lived JWT (5 minutes by default) returned in the body of a successful authentication.
Send it with every request in the `Authorization: Bearer <access token>` header.
* *Refresh token*: long-lived JWT (30 days by default) sent in the `refresh_token` cookie (HTTP-only, Secure, path `/auth/refresh`).
JavaScript cannot read it; the browser sends it automatically to `POST /auth/refresh`, which returns a new access token and replaces the refresh token.

When an access token expires, the API answers `401` with the message "Token has expired": the client should then call `POST /auth/refresh` and retry.

[[conventions-language]]
=== Language

Messages are returned in French by default, or in English.
The language is chosen with the `lang` query parameter (`?lang=en`), otherwise with the `Accept-Language` header.

[[conventions-roles]]
=== Roles and permissions

[cols="1,1,1,1,1"]
|===
|Role |`user:read` |`user:write` |`user:update` |`user:delete`

|`USER` |yes | | |
|`MANAGER` |yes |yes |yes |
|`ADMIN` |yes |yes |yes |yes
|===

In addition, only an `ADMIN` can grant the `ADMIN` role or act on an admin account, and nobody can change the role of, or delete, their own account.

[[azure]]
== Azure login

. The client application sends the browser to `GET /oauth2/login/azure`.
. The user logs in with Microsoft.
. The browser comes back to the client application with `loginType=azure`, `authCode` and `userId` query parameters.
. The client application exchanges the code for tokens with `POST /oauth2/token`.

Tokens never appear in URLs: only a one-time code, valid 5 minutes by default.

[[azure-login]]
=== `GET /oauth2/login/azure`

Starts the Azure login.
The URL to come back to is the `redirectUrl` parameter, or else the `Referer` header.
It must be a path of this server or belong to one of the allowed client origins (`cors.allowed-origins`); otherwise `/auth/redirect-after-login` is used, so that the code cannot be sent to a third-party site.

include::{snippets}/oauth2/login-azure/http-request.adoc[]
include::{snippets}/oauth2/login-azure/http-response.adoc[]

[[azure-success]]
=== `GET /oauth2/success`

Called by Spring Security once Microsoft has authenticated the user; never called directly by clients.
The user is created with the `USER` role on first login, then the browser is redirected to the client application:

----
HTTP/1.1 302 Found
Location: http://localhost:3000/callback?loginType=azure&authCode=3f0c...&userId=42
----
